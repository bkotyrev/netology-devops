# Микросервисы: масштабирование

## Задача 1. Кластеризация

В целом **Kubernetes** - индустриальный стандарт. Закрывает все требования стандартными средствами.

### Поддержка контейнеров

Kubernetes работает с Docker образами. Образы забираются из Nexus.

### Обнаружение сервисов и маршрутизация

- **CoreDNS** позволяет обращаться к сервисам по DNS-именам вместо IP-адресов конкретных Pod.
- **Ingress Controller** маршрутизирует входящие HTTP/HTTPS-запросы к соответствующим сервисам.

### Горизонтальное масштабирование

Для горизонтального масштабирования достаточно изменить количество реплик в Deployment. Kubernetes запустит дополнительные Pod и распределит их по доступным узлам кластера.

### Автоматическое масштабирование

**Horizontal Pod Autoscaler (HPA)** управляет количеством реплик приложения в зависимости от нагрузки. Для HPA задаются минимальное и максимальное количество реплик и целевые значения метрик. Например, поддерживать минимум 2 экземпляра приложения, увеличивая их количество при росте загрузки CPU.

### Разделение внутренних и внешних ресурсов

- **ClusterIP** для внутренних микросервисов, которые не должны быть доступны извне кластера.
- **Ingress и LoadBalancer** для публикации внешних API и других публичных точек входа.
- **Namespace** для логического разделения приложений, команд и окружений.
- **NetworkPolicy** для ограничения сетевого взаимодействия между отдельными сервисами и пространствами имён.

Обычно БД и внутренние API внутри кластера, а внешний запросы задаются через Ingress.

### Конфигурация приложений и хранение секретов

Kubernetes поддерживает переменные окружения и централизованные менеджеры секретов вроде  HashiCorp Vault.

- **ConfigMap** для обычных параметров приложения: адресов сервисов, режимов работы, настроек подключения.
- **Kubernetes Secrets** для паролей, токенов и ключей доступа с ограничением прав через RBAC.
